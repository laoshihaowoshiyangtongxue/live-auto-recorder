# 直播自动录制（抖音版）

自动监控关注主播，后台拉流**原画直拷**录制，同步采集弹幕，下播自动产出**双版本**：无弹幕版 + 弹幕烧录版。支持多主播并发、NVIDIA 编码加速和软件编码回退；烧录与完整性检查耗时取决于录像长度、分辨率、帧率及硬件。

## 快速开始

```bash
npm start
```

弹出主界面（仪表盘）：
- **添加监控**：粘贴直播间链接或房间号（如 `https://live.douyin.com/123456789012`），可加备注名
- 状态列：`离线 / 直播中 / ● 录制中`（脉冲红标），实时显示已录时长、文件大小、弹幕条数
- **观看**：直播中可点「观看」弹出独立直播窗口（可全屏），关闭窗口**不影响**录制
- **设置**：轮询间隔（默认 3 秒）、最大并发、磁盘水位、弹幕烧录开关、是否保留无弹幕版
- 开播/录制完成有**系统通知**
- **关闭窗口 = 最小化到托盘继续录制**；退出请用托盘图标 → 退出（会优雅封存正在录的文件）

也可以直接编辑 `config.json`（10 秒内热重载，无需重启）：

```json
{
  "watchlist": [
    { "rid": "123456789012", "name": "示例主播" },
    { "rid": "123456789012", "name": "另一个主播", "maxSec": 3600 }
  ],
  "settings": {
    "pollIntervalSec": 3,
    "maxConcurrentRecordings": 6,
    "minFreeGB": 5,
    "burnDanmaku": true,
    "keepRaw": true
  }
}
```

- `maxSec`：可选，单段录制时长上限（测试用）
- `keepRaw: false`：烧录成功后自动删除无弹幕版，省一半磁盘（弹幕 jsonl 保留，随时可重新生成）

## 产物（recordings/）

录像按直播间分类保存在 `recordings/主播名_房间号/`。同一场的原版、弹幕版与弹幕JSONL放在同一文件夹；按房间号复用已有目录，主播改名不会产生重复分类。文件名仍保留起录时间，方便区分不同日期和场次。录像保留天数设置同样适用于分类目录，活动任务、临时文件和损坏原片备份不会被清理。

| 文件 | 说明 |
|---|---|
| `直播日期_主播名_开播时间_内容主题_纯享版.mp4` | **无弹幕版**：正常源采用直拷；受损源按验证结果恢复时可能重新编码，损坏原件保留并明确提示 |
| `直播日期_主播名_开播时间_内容主题_弹幕版.mp4` | **弹幕版**：滚动弹幕烧录进画面，NVENC 高质量档（无 N 卡自动回退软编） |
| `主播_房间号_起录时间.danmaku.jsonl` | 原始弹幕记录（墙钟时间戳），可离线重烧 |
| `主播_房间号_起录时间.danmaku-status.json` | 发生写入故障时的弹幕采集缺口记录 |

弹幕版画面只显示评论正文，不显示发言者用户名；原始弹幕记录保留采集信息。

正式视频在后处理成功后统一命名，例如 `2026-10-26_示例主播_13-29-13_示例主题_纯享版.mp4`。日期和时间使用该场起录时间，主题使用开录时保存的直播标题；非法字符会替换，过长内容会截短。同名场次自动添加序号，不覆盖已有文件。已完成旧录像在程序启动后同步改名并更新历史索引，改名中途退出可以继续恢复；处理中的分片及原始弹幕记录保留内部名称。

断流自动换 `part2/part3...` 续录；下播统一转封装 + 烧录。

当前设置为不定时分段（`segment: "0"`），开启自动合并、弹幕烧录和保留原片，最小处理大小为0。正常录完后输出整场原版和整场弹幕版两个MP4。重连失败且确认未写入任何字节的空分片不会阻止合并；有实际数据但损坏或缺失的分片仍保留并阻止不完整合并。没有评论的场次也会生成第二个版本，画面与原片相同。

录完会检查输出文件的完整性，验证通过才替换或删除对应源文件；损坏分片和低于处理阈值的分片会保留，并在界面/日志中说明。自动合并只裁去数据包指纹能够唯一确认的重放区；不能确认时保留原内容，不推测裁剪。关闭自动合并时，弹幕版也保持分段。

「停录」会停止本场的自动录制；可以点击「继续」主动恢复，或等确认下播后自动监控下一场。标题过滤和值守时段通过应用内对话框编辑。输出目录与后处理设置支持热重载，新目录用于后续录像；正在录制的场次保留起录时的后处理设置。

## 后处理静音时段

在设置中勾选「启用后处理静音时段」，自行填写每天的开始、结束时间后保存；支持跨午夜，按电脑本地时间执行。默认不启用。

静音时段只阻止新的后处理任务开始，录制及弹幕采集不受影响。已开始修复或合并的任务会继续生成弹幕版，完整跑完；尚未开始的任务显示「静音时段等待」，在时段结束或关闭静音设置后自动恢复。修改静音设置立即作用于等待中的任务，不采用录像开始时的旧设置。排队记录持久保存，退出和重启不会丢失任务，也无需等到静音结束才能退出。

## 异常恢复与重试

- `recording-jobs.json` 及其 `.bak` 保存任务阶段、分片时间轴、设置和失败原因。程序异常退出后，下次启动会恢复未完成任务，也会扫描符合本应用命名规则的旧遗留文件。待恢复期间请保留这些状态文件和原始素材。
- 后处理失败不会再作为双版本完成通知；失败原因保存在历史和任务面板中，重启后仍可查看。临时失败按退避自动重试，连续三次失败后可在后处理面板点击「重试」。
- 合并、转封装和弹幕烧录都会检查额外空间，处理期间也巡检剩余空间。空间不足时保留原片和任务，显示「等待恢复」，空间恢复后再尝试；正常退出不必无限等待空间恢复。
- 弹幕文件短暂写入失败会重开文件并继续采集；故障期间没有收到或没有成功写入的评论无法保证补回，界面与故障记录会说明缺口。
- 主页发现的房间会核验所属主播身份；主界面渲染器崩溃时自动重载界面，后台录制保持运行。

## 架构（src/）

```
main.js             主进程：主窗口/托盘/系统通知/IPC/单实例
core/
  session.js        抖音会话：热身页 + 页面内fetch（绕风控核心）
  scheduler.js      调度器：状态机、并发上限、磁盘水位、配置热重载、GUI快照
  adapter/douyin.js 平台适配层（统一房间信息 + 最高画质档选择）
  recorder.js       ffmpeg 封装：直拷录制/风暴保护续录/转封装/弹幕烧录(NVENC→x264回退)
  danmaku.js        弹幕采集：隐藏房间页 MutationObserver
  postprocess.js    烧录队列：jsonl→ASS(泳道防重叠滚动)→调Recorder烧录
  job-store.js      原子持久化任务与分片记录
  recovery.js       启动恢复、持久化失败状态、退避与手动重试
  flv-tail-async.js 尾部结构检查的工作线程入口，避免阻塞主进程
gui/                仪表盘（原生JS，无框架依赖）
```

## 验证

运行 `npm test` 执行自动化测试；测试使用隔离数据。

## 说明与限制

- 完整性检查会在录完后解码验证文件，耗时和 CPU 使用量取决于录像长度；检测失败时优先保留源文件。
- 拉流读取超时或持续约 15 秒没有媒体进度时会结束卡住的进程，再按重连退避策略续录。
- 回归测试：`npm test`。测试会在 `work/` 或系统临时目录生成隔离媒体，不连接直播平台，也不改监控配置。

- 帧率/画质上限 = 主播推流 + 平台网页端给出的最高档（自动选最高）
- 开播前 1~3 秒画面物理上无法获取（数据尚未发出）；轮询间隔调小可再压缩
- 硬崩溃或断电可能残留损坏尾部；自动恢复只发布通过检查的产物，不能恢复从未收到的内容，无法确认完整时保留原件并提示。
- 个别主播若出现「原画登录墙」，后续版本可加扫码登录增强
- 请仅用于个人观看存档，勿二次传播

## 传媒公司分组与主页导入

- 主播列表按公司折叠；可新建、改名公司，逐个或勾选后批量移动主播。折叠时仍显示录制、暂停、异常及主页监控数量。
- 原有主播默认放在未分组；删除公司只把主播移回未分组，不删除监控或录像。公司、归属和折叠状态保存在 config.json。
- 搜索可匹配主播、房间号、直播标题或公司；搜索期间自动展开匹配组，清除搜索恢复原折叠状态。
- 个人主页导入如果已识别房间号，直接采用秒级监控；离线导入则等首次开播识别，成功保存后永久转为房间号监控。保留备注、过滤条件、时段和公司归属，重复房间合并为一个监控任务。配置保存失败会保留主页任务并重试。
- 秒级发现使用设置里的轮询间隔（默认3秒），实际触发延迟也取决于网络、平台返回速度及监控数量。

### 跨午夜回放的日期归属

跨午夜且在上海时间00:00至06:00前结束的录像，文件日期使用结束日期加“凌晨”；例如2026-10-26 23:56开始、27日凌晨结束，最终名称为2026-10-27凌晨_主播名_23-56-30_直播标题_纯享版/弹幕版.mp4。实际开播时间及录像时间轴不变。其他录像保持按开播日期命名；已完成的历史文件不批量追溯改名。双版本处理完成后一起正常发布。


## 2026-10-27 后处理更新

媒体处理采用共享预算与独立任务字幕，默认两路。正常暂停挂起同一媒体进程，保留当前进度；恢复、封存、校验、烧录均可暂停。退出后保留暂停状态，未完成阶段下次重新执行。首次完整解码检查保留，仅对身份与内容元数据未变化的文件复用成功结果；并发校验去重、时长探测缓存均在内存中。直播录制独立，后处理使用较低 CPU 优先级，拉流停滞时限制新增后处理。弹幕编码保留可变帧时间间隔，最终仍输出完整纯享版和弹幕版。

## 后处理与上传体积

后处理支持单任务暂停、继续、取消和重试；检查或发布出错时可复用已完成且仍匹配的结果。单个视频在烧录中断后仍需要重新烧录当前分片。新生成的超大 MP4 会在完整性验证后拆成小于 15.5 GB（十进制）的上传分段，原文件归档保留；原有录像不会批量拆分。

主播可单独暂停或恢复监控；暂停时会结束当前录制并保存已录内容。
